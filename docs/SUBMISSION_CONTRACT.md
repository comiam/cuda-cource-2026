# Правила сдачи лабораторных

Здесь описаны структура работы, сборка, запуск и оформление отчёта. При открытии и обновлении PR GitHub Actions проверяет файлы, описание PR и README.

## Папка и обязательные файлы

Размещайте работу в `works/<github-login>/lab<N>/`, где `N` — номер от 1 до 5. Название папки должно совпадать с вашим логином GitHub; регистр букв значения не имеет. В один PR включайте только одну лабораторную, в том числе при удалении и переименовании файлов.

В каждой работе нужны:

- `README.md` — отчёт;
- `CMakeLists.txt` — сборка;
- `src/` с хотя бы одним исходником `.cu`.

По необходимости добавьте `include/`, `tests/`, `data/` и другие каталоги. Разбиение исходников и заголовков на файлы выбирайте сами.

Лимиты: 10 MiB на файл, 25 MiB и 1000 файлов на лабораторную, 1000 изменённых файлов в PR. В Git храните исходники, отчёт и небольшие примеры, например PNG. Датасеты и веса получайте по инструкции из отчёта. Сборочные файлы, виртуальные окружения, сырые профили, симлинки и submodules в сдачу не входят.

## Сборка

Используем CMake. Из каталога лабораторной выполните:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target submission
```

Назовите цель `submission`; собранная программа должна находиться в `build/submission`.

## CLI программы

```bash
./build/submission --help
./build/submission --input <путь> --output <путь> [--mode <режим>]
```

Для запуска нужны `--input` и `--output`. Флаг `--mode` необязателен: без него используется режим из таблицы. Команда `--help` запускается отдельно и описывает аргументы, режимы и форматы данных.

| Работа | Обязательные режимы                                     | По умолчанию |
| ------ | ------------------------------------------------------- | ------------ |
| Lab 1  | `coalesced`, `noncoalesced`; в каждом add, SAXPY и ReLU | `coalesced`  |
| Lab 2  | `naive`, `tiled`                                        | `tiled`      |
| Lab 3  | `global`, `shared`                                      | `shared`     |
| Lab 4  | `train`, `eval`                                         | `eval`       |
| Lab 5  | `train`, `eval`                                         | `eval`       |

Дополнительные параметры и режимы опишите в README и `--help`. В Lab 3 вход и результат — PNG. Для `eval` нужны сохранённые веса и входные данные; если их нет, сообщите об ошибке.

Программа должна работать без интерактивного ввода. Относительные пути считайте от каталога запуска, абсолютные используйте как переданы. Форматы входов и результатов опишите в README.

Результат сохраняйте в `--output`, логи выводите в `stdout`, ошибки — в `stderr`. Коды возврата: `0` — успех, `2` — неверные аргументы или входные данные, `1` — ошибка выполнения.

## Заголовок и описание PR

Оформите заголовок по образцу:

```text
Иванов И.И. M4101. Lab 1: Vector Operations and Activations
```

В фамилии допустимы кириллица, латиница, дефис и апостроф. Инициалы пишите заглавными буквами с точками — одна или две буквы. Группа — заглавная латинская или кириллическая буква и 4–6 цифр. Номер лабораторной должен совпадать с папкой. Используйте следующие названия:

| Номер | Название                          |
| ----- | --------------------------------- |
| 1     | Vector Operations and Activations |
| 2     | Matrix Multiplication             |
| 3     | Sobel Operator                    |
| 4     | cuDNN Perceptron                  |
| 5     | AlexNet-style CNN on CIFAR-100    |

В описании PR заполните разделы `Что сделано`, `Проверка`, `Отчёт`. В последнем дайте относительную ссылку на README лабораторной от корня репозитория. Подробные команды, измерения и объяснения оставьте в самом отчёте.

Общие документы и CI обновляются отдельными PR сопровождающих курса.

## Основной README

Используйте разделы с заголовками уровня `##`:

- `Описание`;
- `Окружение`;
- `Компиляция`;
- `Запуск`;
- `Проверка корректности`;
- `Результаты`;
- `Выводы`;
- `Воспроизводимость`.

Для Lab 3–5 добавьте `Профилирование и оптимизация`. В Lab 1–2 профилирование — по желанию.

Опишите своё решение, проверки и результаты. Команды в разделах `Компиляция` и `Запуск` оформите блоками кода. Проверьте, что относительные ссылки и изображения ведут на файлы внутри репозитория.

### Как воспроизвести результаты

В `Окружение` укажите GPU, драйвер, CUDA, компилятор и версии библиотек. В разделе `Воспроизводимость` добавьте подразделы уровня `###`:

- `Данные` — откуда взять входы или как их сгенерировать;
- `Полный запуск` — команды от чистой сборки до получения результатов.

Для Lab 4–5 также нужны:

- `Параметры обучения` — seed, гиперпараметры и разбиение данных;
- `Загрузка весов` — где получить веса, как их загрузить и запустить оценку.

Для больших данных и весов приведите источник и команды получения.

## Форматирование

Используйте конфиги курса. Версии инструментов закреплены в `.ci/requirements.txt`. CI проверяет:

| Файлы                                                                                           | Инструмент        |
| ----------------------------------------------------------------------------------------------- | ----------------- |
| C/C++/CUDA и заголовки: `.c`, `.cc`, `.cpp`, `.cxx`, `.h`, `.hh`, `.hpp`, `.hxx`, `.cu`, `.cuh` | clang-format      |
| `.py`                                                                                           | Ruff format       |
| `CMakeLists.txt`, `.cmake`                                                                      | cmake-format      |
| Основной `README.md` лабораторной                                                               | Проверка Markdown |

Линтинг ограничен этой таблицей. Лимиты размера, правила путей и состава действуют для всех файлов работы.

Результат смотрите в PR: статус `submission/static`, подробности — в отчёте запуска GitHub Actions.

Задания лабораторных находятся в [works/README.md](../works/README.md).
