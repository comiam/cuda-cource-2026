# Lab 1: Vector Operations and Activations — Векторные операции и активации

[К списку лабораторных](README.md)

## На чём фокус

В этой лабораторной разбираемся с основами: как запустить ядро, распределить элементы между потоками, передать данные на GPU и получить результат обратно. Здесь каждый поток делает независимую работу — это паттерн Map.

## Что я жду от вас

Вы должны сами реализовать CUDA-ядра для трёх операций над векторами типа `float`:

- сложение векторов;
- SAXPY: `y = a * x + y`;
- ReLU: `y = max(0, x)`.

Размер массива считывайте из входного файла. Программа должна работать и с маленькими массивами, и с размерами, не кратными блоку. Проверяйте границы массива и ошибки CUDA, освобождайте память. Пустой вход можно либо корректно обработать без запуска ядра, либо отклонить с понятным сообщением.

Сравните коалесцированный и некоалесцированный доступ: выполните ту же логическую операцию над тем же количеством элементов, но измените организацию обращений к памяти. Shared memory и обучение сети пока не нужны.

## Как проверить и что измерить

- Сравните каждую операцию с готовой функцией или коротким библиотечным выражением. Для SAXPY сохраните исходный `y`: ваша операция и эталон должны получить одинаковые входы.
- Проверьте нули, значения разных знаков и размеры около границы блока, например 255, 256 и 257 элементов. Укажите допуски и максимальную ошибку.
- Отдельно измерьте H2D, ядро, D2H и полный цикл H2D → ядро → D2H. Выделение памяти измеряйте отдельно либо явно включите в полное время.
- На большом массиве сравните несколько размеров блока и оба варианта доступа к памяти. Использовать профилировщик можно, но в этой работе он не обязателен.

## Что показать в отчёте

Покажите, как индекс потока связан с элементом массива, приведите проверки и собственные замеры. Я жду объяснения, почему одна организация доступа лучше другой и когда передачи CPU↔GPU стоят дороже самого вычисления. Одной таблицы времени без выводов недостаточно.

## CLI и форматы файлов

Режимы `--mode`: `coalesced` и `noncoalesced`. [Общие правила запуска](../docs/SUBMISSION_CONTRACT.md#cli-программы).

**Вход:** `N alpha`, затем `N` пар `x y`.

**Выход:** для каждой пары запишите `x+y`, `alpha*x+y` и `max(0,x)` в исходном порядке. Заголовка в выходе нет. Оба режима делают все три операции; по умолчанию — `coalesced`.

Для `N=0` можно записать пустой файл либо отклонить вход с сообщением об ошибке. Выбранное поведение укажите в README.

Файл текстовый: числа разделены пробельными символами; дробная часть пишется через точку. Вход читается в FP32; для вывода достаточно 9 значащих цифр. Пишите данные в `--output` без логов и лишних значений.

Сложение и ReLU должны совпадать в FP32. Для SAXPY допустимы как отдельное умножение и сложение с округлением в FP32, так и FMA. Числовой `+0` равен `-0`.

## Пример для самопроверки

Сохраните этот вход в `lab1.txt`:

```text
3 0.5
-3 2
1 -5
4 0.5
```

Ожидаемый файл результата:

```text
-1 0.5 0
-4 -4.5 1
4.5 2.5 4
```

```bash
./build/submission --input lab1.txt --output lab1-coalesced.txt
./build/submission --input lab1.txt --output lab1-noncoalesced.txt --mode noncoalesced
```

Сравните оба выходных файла с приведённым результатом.
