# Lab 1: Vector Operations and Activations

## Описание

Программа запускает три CUDA-ядра над векторами `float`: сложение, SAXPY и ReLU. У каждой операции свой выходной вектор. SAXPY читает исходный `y` и выполняет умножение и сложение с отдельным округлением в FP32.

На GPU выделяются пять отдельных буферов по `N * sizeof(float)` байт: два для входов и три для результатов. Префикс `h` означает host (память CPU), а `d` — device (память GPU). Например, H2D копирует `hX` в `dX`, а D2H копирует `dAdd` в `hAdd`. При выходе из `compute` каждый буфер GPU освобождается через `cudaFree`.

Для блока из `B` потоков запускаем `ceil(N / B)` блоков. Глобальный номер потока считаем как `t = blockIdx.x * blockDim.x + threadIdx.x`. Потоки с `t >= N` выходят до чтения или записи. Остальные читают и записывают один элемент с индексом `i`.

- В режиме `coalesced` берём `i = t`. Соседние потоки warp обращаются к соседним элементам каждого вектора.
- В режиме `noncoalesced` делим линейные индексы на плитки по 1024 элемента. Внутри каждой полной плитки представляем локальный номер `j` как координаты `(j / 32, j % 32)` и меняем их местами. Получаем `i = base + (j % 32) * 32 + j / 32`. Хвост короче 1024 обрабатываем линейно.

Например, первые четыре потока полной плитки получают такие индексы:

```text
t              0    1    2    3
coalesced      0    1    2    3
noncoalesced   0   32   64   96
```

Транспонирование — перестановка индексов внутри плитки, поэтому каждый элемент вычисляется ровно один раз. Запись по индексу `i` сохраняет исходный порядок строк. Shared memory не используется.

- [src/kernels.cu](src/kernels.cu) реализует три ядра. Параметр `bool noncoalesced` одинаков для всех потоков одного запуска и выбирает способ вычисления индекса.
- [src/gpu.cu](src/gpu.cu) выделяет память, копирует данные, запускает ядра напрямую через `<<<grid, block>>>` и измеряет время.
- [src/main.cpp](src/main.cpp) разбирает аргументы, читает вход и записывает результат.

## Окружение

Локальный запуск: NVIDIA GeForce RTX 4070 Ti, драйвер 617.14, Windows (WDDM), CUDA Toolkit 13.1.80, MSVC 19.50.35729, CMake 4.2.3-msvc3. Для проверок использованы Python 3.12.14 и NumPy 2.3.5.

Из каталога лабораторной:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release

```

## Запуск

```bash
./build/submission --help
./build/submission --input data/sample.txt --output build/coalesced.txt
./build/submission --input data/sample.txt --output build/noncoalesced.txt --mode noncoalesced
```

В Windows исполняемый файл называется `build/submission.exe`. Вход содержит `N alpha` и ровно `N` пар `x y`, разделённых пробелами или переносами строк. Вещественные входы считываются как конечные FP32 с десятичной точкой. Результат состоит из трёх чисел на строку без заголовка, с точностью до 9 значащих цифр. Для `N = 0` создаётся пустой файл без запуска CUDA.

Режим по умолчанию — `coalesced`. Параметр `--block-size N` задаёт от 1 до 1024 потоков в блоке, по умолчанию 256. Параметр `--repeat N` включает один прогрев и `N` измеряемых циклов с выводом медиан в stdout. При пустом входе замеров нет.

## Выводы

На большом входе коалесцированный режим сократил суммарное время ядер в 1.43–1.70 раза в зависимости от размера блока. При выровненном линейном доступе 32 потока warp читают 128 соседних байт одного вектора, которые укладываются в четыре 32-байтных сектора. В режиме с шагом 32 элемента соседние потоки разнесены на 128 байт и обращаются к 32 разным секторам. Часть секторов затем переиспользуется через кеш, поэтому соотношение числа секторов нельзя напрямую перевести в ускорение. Для 257 элементов оба режима обрабатывают только линейный хвост, а разница во времени показывает разброс коротких запусков.

На большом входе с блоком 512 в режиме `coalesced` сумма медиан H2D и D2H составила 104.8 мс, а медиана времени ядер — 1.34 мс. При переходе в `noncoalesced` медиана полного цикла выросла примерно на 0.82 мс. На этой серии блок 512 дал самое короткое время ядер в линейном режиме. Замеры сделаны на рабочем столе Windows с WDDM и обычной памятью CPU, поэтому небольшие различия полного времени и лучший размер блока могут измениться на другой машине. Выигрыш ядра станет заметнее, когда данные уже находятся на GPU и между операциями нет копирования на CPU.
