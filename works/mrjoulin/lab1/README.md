# Lab 1: Vector Operations and Activations — Векторные операции и активации

## Описание

Реализованы собственные CUDA-ядра для трёх поэлементных операций над векторами `float`:

- `add`: `c[i] = a[i] + b[i]`;
- `saxpy`: `y[i] = alpha * x[i] + y[i]`;
- `relu`: `y[i] = max(0.0f, x[i])`.

Для каждой операции реализованы два варианта доступа к глобальной памяти:

- **coalesced** — последовательные треды в warp читают/пишут последовательные элементы массива;
- **noncoalesced** — каждый тред обрабатывает сплошной непрерывный фрагмент из `64` элементов, поэтому соседние треды обращаются к далёким адресам с шагом `64 * sizeof(float)`, нарушая коалесцентность.

Проверка корректности выполняется с помощью эталонной реализации на CPU (то же арифметическое выражение). Входы генерируются детерминированно по `seed`.

## Окружение

Запуск производился на удалённом GPU-сервере:

- **GPU:** Quadro RTX 6000, compute capability 7.5, 24 GiB
- **CUDA Toolkit:** 12.9
- **CMake:** 3.28.3
- **Компилятор:** NVCC 12.9 (GCC 13.3 backend)
- **ОС:** Linux
- **Архитектура сборки:** `sm_75`

## Компиляция

Из каталога лабораторной:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target submission
```

## Запуск

```bash
./build/submission --help
./build/submission --input data/params.txt --output results/coalesced
./build/submission --input data/params.txt --output results/noncoalesced --mode noncoalesced
```

Формат входного файла — текстовый `key=value`, см. `data/params.txt`. Поддерживаемые ключи:

- `n` — размер большого массива для замеров;
- `alpha` — коэффициент SAXPY;
- `seed` — seed генератора входов;
- `block_size` — число тредов в блоке (`0` — прогон 64, 128, 256, 512, 1024);
- `repeats` — число повторений после разогрева.

Результаты сохраняются в `--output/report.txt`.

## Реализация

- `include/kernels.h` — объявления операций и режимов доступа.
- `src/kernels.cu` — шесть ядер (coalesced/noncoalesced × add/saxpy/relu).
- `include/config.h` / `src/config.cpp` — разбор аргументов командной строки и загрузка конфигурации.
- `include/report.h` / `src/report.cpp` — структуры результатов и генерация отчёта.
- `src/main.cu` — генерация входов, валидация на малых размерах, бенчмарк с CUDA events.

Распределение элементов по тредам:

- **coalesced:** `idx = blockIdx.x * blockDim.x + threadIdx.x`, шаг `gridDim.x * blockDim.x`, проверка `idx < n`;
- **noncoalesced:** каждый тред получает фиксированный чанк `kChunk = 64` элементов, начиная с `tid * kChunk`, граница обрезается до `n`. Размер сетки выбирается как `(ceil(n / kChunk) + block - 1) / block`.

Границы массива проверяются в обоих режимах. При `n == 0` ядро не запускается. Все вызовы CUDA обёрнуты макросами `CUDA_CHECK` / `CUDA_CHECK_KERNEL`, память освобождается.

## Проверка корректности

Эталон — последовательная реализация на CPU с теми же формулами. Проверялись размеры `0, 1, 255, 256, 257, 1023, 1024, 1025` для всех трёх операций в обоих режимах. Допуск на несовпадение — `1e-5`. Для SAXPY эталон получает тот же исходный `y`, что и GPU-ядро.

| Режим | Проверенные размеры | Операции | Максимальная ошибка | Несовпадений (>1e-5) |
|---|---|---|---|---|
| coalesced | 0, 1, 255, 256, 257, 1023, 1024, 1025 | add, saxpy, relu | 0.00e+00 | 0 |
| noncoalesced | 0, 1, 255, 256, 257, 1023, 1024, 1025 | add, saxpy, relu | 0.00e+00 | 0 |

Также для массива `n = 16 777 216` после бенчмарка выполнялась повторная проверка всех трёх операций — ошибок не обнаружено.

## Результаты

Замеры выполнялись с помощью CUDA events, синхронизация через `cudaEventSynchronize`. После двух разогревочных прогонов берётся медиана `20` повторений. Время полного цикла включает H2D-копии, ядро и D2H-копию, но **не включает** однократное выделение памяти.

Размер массива: `16 777 216` элементов (`64 MiB`), `alpha = 2.0`, `seed = 2026`.

### Основные замеры при block_size = 256

| Режим | Операция | H2D, мс | Ядро, мс | D2H, мс | Полный цикл, мс |
|---|---|---|---|---|---|
| coalesced | add | 29.31 | 0.35 | 14.08 | 43.78 |
| coalesced | saxpy | 29.48 | 0.35 | 14.21 | 44.06 |
| coalesced | relu | 14.17 | 0.24 | 13.95 | 28.35 |
| noncoalesced | add | 29.17 | 8.17 | 13.87 | 51.28 |
| noncoalesced | saxpy | 29.05 | 6.98 | 13.88 | 50.03 |
| noncoalesced | relu | 14.15 | 6.93 | 13.80 | 34.87 |

### Влияние размера блока (время ядра, мс)

| Режим | Операция | 64 | 128 | 256 | 512 | 1024 |
|---|---|---|---|---|---|---|
| coalesced | add | 0.352 | 0.350 | 0.350 | 0.351 | 0.351 |
| coalesced | saxpy | 0.349 | 0.349 | 0.349 | 0.350 | 0.350 |
| coalesced | relu | 0.243 | 0.239 | 0.239 | 0.240 | 0.240 |
| noncoalesced | add | 8.199 | 8.137 | 8.131 | 8.273 | 8.128 |
| noncoalesced | saxpy | 7.064 | 7.006 | 6.961 | 7.168 | 7.132 |
| noncoalesced | relu | 6.998 | 6.934 | 6.934 | 7.028 | 6.748 |

Время выделения памяти замеряется отдельно и в полный цикл не входит; в большинстве прогонов оно составляет `0.3–1.6 мс`, но иногда пул памяти CUDA даёт выбросы до `~155 мс`.

## Выводы

1. **Коалесцентный доступ значительно быстрее.** При `block_size = 256` ядро `add` ускоряется с `8.17 мс` до `0.35 мс` (≈23×), `relu` — с `6.93 мс` до `0.24 мс` (≈29×). Это соответствует ожидаемому эффекту: warp в coalesced-варианте выполняет один широкий запрос к памяти, а в noncoalesced — множество разрозненных.
2. **Размер блока почти не влияет на ядро.** Для memory-bound операций с таким массивом основным ограничением является пропускная способность памяти, а не occupancy или число блоков. Разброс времени ядра в пределах `±3%` подтверждает это.
3. **Передачи данных дороже вычислений.** Даже в coalesced-режиме H2D+D2H занимают `≈43–44 мс`, тогда как само ядро — менее `0.4 мс`. Для add/saxpy полезная работа составляет менее `1%` полного цикла, для relu — около `0.9%`.
4. **Накладные расходы GPU окупаются только при достаточном объёме вычислений.** На массиве `64 MiB` переносы доминируют; ускорение ядра за счёт coalescing снижает полный цикл, например для `relu`, на `≈18%`, потому что основное время уходит на PCIe-копии.
5. **Проверка границ работает корректно:** нулевой размер, размеры меньше блока и не кратные блоку обрабатываются без ошибок.
